# Codex 聊天合并工具（Windows）

用于把两台电脑的 **Codex 本地聊天记录、聊天标题及项目分组** 合并。提供中文窗口、Git 仓库同步和本地命令行。Python 3.10 以上即可运行本地合并；Git 同步需要 Git for Windows，加密上传另需 `cryptography`。

这是依据当前安装版本的数据结构编写的本地迁移工具，**不是 Codex 官方导入接口**。数据库结构不一致时拒绝合并。已用当前版本的数据库建表语句和人工构造的聊天做自动化测试；尚未在两台真实电脑的 Codex 中验证恢复后的界面及续聊行为。

## 获取完整工具

源码仓库：[maycode0-0/ChartGpt-Merge](https://github.com/maycode0-0/ChartGpt-Merge)，工具分支为 `codex/tool-source`。仓库包含完整源码、启动脚本、说明和测试。拉取后直接运行 `start.cmd`，无需另行打包或解压工具。

```powershell
git clone --branch codex/tool-source git@github.com:maycode0-0/ChartGpt-Merge.git
cd ChartGpt-Merge
python -m pip install -r requirements.txt
.\start.cmd
```

需要 Python 3.10 或以上、Tcl/Tk，以及 Git for Windows。`start.cmd` 调用同目录的 `codex_chat_merge.py`、`chat_merge_gui.py` 和 `git_chat_sync.py`，请将这些文件保留在一起。

## 最先知道的三件事

1. **导出和应用前，完全退出 Codex / ChatGPT，包括托盘、后台进程。操作过程中不要重新打开。** 工具会检测相关进程，不会自动结束它们。
2. 合并先发生在新的工作目录，**不会直接修改你正在使用的聊天库**。只有在预览页点击“应用到本机”才会写入本机 `.codex`。
3. 不同聊天可以合并；同一聊天分别续聊产生的分叉 **不会拼成一条聊天，也不会伪造新的聊天 ID**。默认停止并输出报告。你可以选择在 Codex 显示其中一版，另一版完整保留在快照备份中。

## 打开工具

1. 两台 Windows 电脑都安装 [Python 3.10 或更高版本](https://www.python.org/downloads/windows/)，保留安装选项中的 Tcl/Tk 支持。两边 Codex 使用相同版本和安装渠道，建议使用同一账号。
2. 克隆完整仓库，或将完整源码文件夹复制到本机。
3. 完全退出 Codex / ChatGPT。
4. 双击 `start.cmd`。也可以在 PowerShell 执行：

   ```powershell
   python .\codex_chat_merge.py
   ```

窗口的默认聊天目录是当前用户的 `%USERPROFILE%\.codex`。如果设置过自定义 `CODEX_HOME`，请手动选择实际目录。

目录输入、冲突处理方式、导出范围和项目 / 聊天勾选会自动保存在本机，下次打开恢复。按项目选择时会重新读取列表，保留仍存在的勾选；完整项目会包含新增聊天。更换 `.codex` 目录后需重新读取并选择。

## 按项目选择导出内容

在 **本地导出 / 合并** 页内的 **导出范围（按项目）** 区域操作：

1. 点击 **读取 / 刷新项目**，按项目显示聊天数量，展开可看到每条聊天的标题和归档状态。
2. 点击项目旁的方框，勾选整个项目；也可以展开后仅勾选需要的几条聊天。
3. 支持同时选择多个项目，以及另外添加其他项目中的单条聊天。也可以“全选项目”后取消不需要的项目。
4. 区域内会显示当前导出范围。点击本页的 **导出到本地文件夹**，或切到 Git 标签页点击 **备份并上传**，两处都会使用这个选择。
5. 要恢复完整备份，选择 **全部聊天**。清空勾选后不会默认为全部导出，而是要求选择内容。

项目列表优先读取应用中明确的分组记录，其次读取数据库项目关联；没有明确关联时，根据聊天工作目录匹配最具体的项目根目录。列表中会标明“目录推断”，不能唯一判断的放在 **未分组聊天**。明确标为未分组的聊天不会再按目录强行归组。更改 `.codex` 路径后需要重新读取列表。

每份导出还包含 `projects.json`，按项目列出导出的聊天 ID、标题、归档状态和归属依据。它是备份清单，不会写入正在使用的 `.codex`。同名项目可通过项目目录区分，命令行则可使用唯一的项目 ID。

按项目导出会从头建立只含选中记录的 SQLite 数据库，并只复制这些聊天对应的原始日志。未选项目的消息、标题索引、附件记录、项目配置，以及未索引的日志不写入快照；未选记录也不会残留在数据库空闲页中。此模式不会复制另一台机器的自动化任务、通知等无关表的数据。已没有日志文件的 `paginated` 聊天仍会导出其数据库历史。

筛选以整条聊天为单位，不截取聊天中的部分消息；选中聊天正文中已经引用的其他信息也会保留，这不是正文脱敏功能。跨项目的父子聊天不会自动全部选中，所需的其他聊天需要另行勾选。未索引、无法可靠识别归属的日志只能用“全部聊天”方式备份。

**选择范围只影响对外导出和 Git 上传。** 合并前仍会完整备份本机记录，把选中项目的来源快照合入本机全量数据，所以不会删除本机其他项目。局部快照不能用作合并的本机基准。

## 第一次合并：公司电脑 → 家里电脑

### 在公司电脑导出

1. 退出 Codex 后打开本工具。
2. 核对“本机 .codex 目录”。你的目录是 `C:\Users\Autumn\.codex`。
3. “工作 / 备份目录”选一个有足够空间的目录，例如 `D:\CodexChatBackups`。该目录应位于 `.codex` 外部。
4. 点击 **导出到本地文件夹**。
5. 日志会显示新建的 `export-日期时间-编号` 目录，里面有 `manifest.json`。
6. 把 **整个导出目录** 带回家。不要只复制 `.sqlite` 文件。

可以通过 U 盘、局域网、加密压缩包或 GitHub 私库传输。导出目录中有校验清单，文件缺失或改变时工具会拒绝使用。

### 在家里合并

1. 完全退出家里的 Codex，启动本工具。
2. “本机 .codex 目录”选择家里的数据目录。
3. “另一台电脑的导出目录”选择刚带回家的 `export-...` 目录，**选择含有 manifest.json 的那一层**。
4. “工作 / 备份目录”选择一个新的本地工作位置。
5. 冲突策略先保持 **停止并生成报告**。
6. 点击 **预览本地合并**。工具会自动导出家里的现有聊天，再合并双方快照。

完成后会生成：

```text
merge-日期时间-编号/
  base/           家里原有记录的完整聊天快照
  incoming/       公司记录的完整聊天快照
  merged/         可应用的合并结果（仅成功后才有有效 manifest.json）
  report.json     新增、更新、保留和冲突清单
```

输入快照和工作输出目录必须互不包含。工具会保留原始副本并再建立合并副本，**请至少预留双方聊天数据总量两倍以上的剩余空间**，应用时还需要回滚备份和安装暂存空间。

### 应用并检查

1. 查看 `report.json` 的 `status` 为 `ready`，检查聊天总数、冲突与警告。
2. 窗口自动打开 **合并预览**，显示新增、更新和分叉数量；无需手填结果目录。
3. 保持 Codex 关闭，点击预览页的 **应用到本机**。
4. 工具会先检查家里的聊天是否在导出后又被改动。如果有变化，会拒绝覆盖，需要重新合并。
5. 应用前会保存所有将被替换或删除的文件，并生成回滚凭据 `rollback-...\receipt.json`。
6. 完成后再启动 Codex，检查双方独有的聊天、项目分组、长聊天和归档聊天，尝试继续一条不重要的聊天。

不要在两个工具实例里同时处理同一目录；工具有进程间文件锁，会拒绝并发处理。这个锁不能阻止用户重新打开 Codex，所以处理过程中仍需保持 Codex 关闭。

## 两台电脑的项目目录不一致

例如公司项目位于 `D:\Work\projectA`，家里位于 `E:\Code\projectA`：

1. 正常点击 **下载并预览合并**，或 **预览本地合并**。
2. 在 **合并预览** 中点击 **修改项目目录…**。即使因项目目录不一致导致首次合并未完成，也可以从该入口调整。
3. 选择项目，将“本机目录”填写或选择为 `E:\Code\projectA`。同名且唯一的本机项目会预填目录，请核对；不需要变更的项目可点 **保持原目录**。
4. 点击 **按此目录重新合并**。工具使用已保留的双方快照生成新的预览，无需再次下载或导出。
5. 检查预览中的映射，再点击 **应用到本机**。

映射只作用于来源电脑的项目根目录、被导入聊天的工作目录、已支持的写入目录字段与应用索引；本机保留的聊天目录不变。子目录随之转换，例如 `D:\Work\projectA\src` 变为 `E:\Code\projectA\src`。路径按 Windows 规则匹配，大小写不敏感；同时存在父目录和子目录规则时，优先使用最长匹配，并且不会连锁替换。

映射规则保存在本机配置，下次合并会自动沿用，并记录在 `report.json`。**项目文件不会搬移或下载，需要事先把源码等文件准备在本机目录。** 聊天正文、历史命令、原始会话日志及其中的旧绝对路径不会改写；来源快照和回滚基准保持原样。

命令行也支持 `merge --path-map path-map.json`，文件内容示例：

```json
{
  "D:\\Work\\projectA": "E:\\Code\\projectA",
  "D:\\Work\\projectB": "F:\\Projects\\projectB"
}
```

## 冲突如何处理

| 情况 | 处理方式 |
|---|---|
| 一台电脑独有的聊天 ID | 导入，保留原始 ID、消息和历史数据库条目 |
| 同一聊天的消息日志完全一致，历史投影一致 | 去重，保留本机元数据 |
| 一份日志是另一份的完整字节前缀 | 选择内容较完整的一方，连同其历史投影一起导入 |
| paginated 格式的聊天已没有原始日志文件 | 按数据库消息主键和完整内容比较；仅新增消息时选完整版本，既有消息不同则判冲突 |
| 消息日志一样，但历史数据库投影不一致 | 保守地判为冲突；一方完全没有投影时使用有投影的一方 |
| 同一聊天两边分别续聊，日志分叉 | 默认停止。可选择显示本机版本或另一台版本 |
| 新增项目根路径和名称一致，但项目 ID 不同 | 合并到本机项目 ID，更新来源聊天的关联 |
| 两边根目录为空、仅项目名称一致 | 不凭名称强行合并，可能保留两个项目 |
| 数据库结构不同、旧格式聊天缺少日志、日志不完整 | 停止，不产生可应用的完整结果 |

默认冲突模式停止后，报告和双方快照仍保留。阅读报告后，可以在窗口改选“显示本机版本”或“显示另一台版本”，再点击合并，会生成一个新的工作目录。**此选择对本次全部冲突生效。没有冲突的独有聊天仍会导入；较长的单向续聊仍按完整版本处理。**

文件长度只用来判断原样追加的消息日志；不使用数据库大小、文件修改时间来决定哪版聊天正确。日志不会重新序列化，因此数据库中引用的字节位置保持不变。

聊天正文相同但改名、置顶、归档状态不同的情况，默认保留本机聊天元数据。项目顺序等存在冲突时也优先保留本机已有设置。未索引的会话文件会被保留并在报告中说明，但不保证会显示在侧边栏。

当前版本的部分旧聊天为 `paginated` 格式，原始日志文件已不存在，但正文仍在历史数据库里。工具会原样保留和比较这些数据库消息，不虚构日志文件。报告的 `database_only_threads` 列出来源中此类聊天，`index_only_threads` 列出其中没有找到消息条目的记录；后者的标题等索引仍会保留，但工具无法恢复来源中已经没有的正文。原始日志不在时，续聊能否正常工作仍需目标 Codex 实测。

## 备份与回滚

点击窗口中的 **回滚**，选择该次应用生成的 `receipt.json`。命令行也支持回滚。

- 应用中途遇到正常的文件写入错误，会尝试自动回滚。
- 突然断电或进程被结束时，下次可以使用已写入磁盘的 `receipt.json` 回滚。
- 如果应用后又打开 Codex 产生了数据变化，自动回滚会拒绝覆盖，避免覆盖新聊天。此时保留双方快照及回滚目录，用新记录重新合并或在副本上处理恢复。
- 一次应用不是跨文件的数据库事务。工具使用逐文件原子替换、预先备份、暂存校验和磁盘凭据降低风险；保留原始快照仍然必要。
- 暂时不要删除 `base`、`incoming`、回滚目录。应用时需要同一工作目录中的 `base`，用于检查目标记录是否已经过时。

## 同步范围

导出以下内容：

```text
sessions/                         整个目录
archived_sessions/                存在时整个目录
state_数字.sqlite                  使用 SQLite 备份 API，包含已提交的 WAL 数据
thread_history_数字.sqlite         同上
sqlite/codex.db                   存在时备份
sqlite/codex-dev.db               存在时备份
session_index.jsonl               存在时备份，合并后从聊天索引重建
.codex-global-state.json          只提取聊天、项目分组及排序相关字段
projects.json                    工具生成的项目分类清单，不写入目标应用
```

上表描述“全部聊天”模式。按项目 / 聊天选择时，仅导出选中记录对应的数据和日志，数据库由选中记录重建。

不会导出 `auth.json`、`config.toml`、系统凭据库、登录令牌、运行日志、浏览器数据、自动化脚本目录或工作区代码。**数据库及聊天文本本身仍可能包含私人内容、过去粘贴的密钥和工具输出；快照不是脱敏数据，也不是加密数据。**

为保留当前数据库结构，导出的应用数据库可能含有原机的自动化配置等已有表。合并时只处理本地聊天目录和时间线，不导入另一台的自动化任务、通知或远程主机注册信息。当前目标数据库中已有的这些内容保留。

合并应用数据库时，会把另一台的本地聊天目录主机 ID 转换为目标本机的主机 ID，并使目标本机的扫描游标失效以便重新扫描。远程 SSH、WSL、远程控制和 ChatGPT 云端主机的目录记录不导入。这些是依赖内部实现的兼容处理，不能代替真实恢复验证。

聊天中指向临时目录、外部图片、生成图片、音视频、工作树或其他绝对路径的文件不会自动收集；文字记录中这些引用仍然保留。两台电脑目录一致有助于路径兼容，但文件本身仍需要存在。

## 用 GitHub 私库传输

默认打开 **Git 仓库同步**。首次在 **连接与设置** 填写仓库和路径；日常在同步页完成备份和导入，项目勾选仍位于 **本地导出 / 合并**。

### 一次性准备

1. 建立一个专门的 GitHub **私有仓库**。可以是空仓库或只有 README、LICENSE 的新仓库；不要使用项目代码仓库。工具不会创建 GitHub 仓库，也不会检测远端仓库的公开/私有状态，请自行确认。
2. 两台电脑安装 [Git for Windows](https://git-scm.com/download/win)。HTTPS 使用已有 Git 凭据管理器，SSH 使用已配置的密钥和可信主机。
3. 保留默认的加密上传选项，在两台电脑安装加密依赖：

   ```powershell
   python -m pip install -r requirements.txt
   ```

4. 在 **连接与设置** 中，两台电脑都填写同一个仓库地址，例如 `https://github.com/你的账号/codex-chat-backups.git`。也支持 `git@github.com:账号/仓库.git`、`ssh://` 和本地绝对路径。
5. 两台电脑填写不同的设备标识，例如 `office`、`home`。默认会生成机器名称加随机后缀；不需要刻意更改。
6. “本地克隆目录”选择独立的本地目录，例如 `D:\CodexChatBackups\git-repo`。不能使用正在工作的项目仓库，也不能位于 `.codex` 内。
7. 返回 **Git 仓库同步** 页，设置同一个备份密码，至少 12 字符，推荐使用密码管理器生成的长密码。**密码不会保存，每次重新打开工具需填写。**

配置会自动保存到 `%LOCALAPPDATA%\CodexChatMerge\settings.json`，包含本地目录、冲突处理方式、导出范围和勾选 ID，以及仓库地址、克隆目录、设备标识、设备归属 ID、是否加密、网络超时和上次打开的页面。无需先点击连接即可记住输入。不会保存 GitHub 令牌、SSH 密钥或备份密码。填写的 HTTPS URL 不能包含账号、密码或令牌。

### 平时怎么使用

公司电脑结束工作：

1. 完全退出 Codex。
2. 打开本工具的 **Git 仓库同步** 页，核对导出范围；需要筛选时点击 **选择项目 / 聊天**。
3. 填写备份密码，点击 **备份并上传**。无需先点连接：工具先检查密码和仓库，再导出、压缩加密、提交并推送。

如果只上传部分项目，先到“本地导出 / 合并”页的“导出范围（按项目）”中勾选。项目分类清单也在加密分卷里，远端不会额外明文公开项目名称和聊天标题。每台设备的“最新快照”指向最近一次上传；若这次仅选择部分项目，拉取它也只会导入这部分项目，旧快照仍留在 Git 历史和快照目录中。

家里电脑开始工作：

1. 完全退出家里的 Codex，打开工具，填入同一个仓库地址和密码。
2. 点击 **刷新远端备份**，在右侧列表中选择公司的设备；列表显示备份时间、是否加密，默认优先选择其他电脑。
3. 点击 **下载并预览合并**。工具解密快照、完整备份家里的现有记录，并生成新合并目录。
4. 自动进入 **合并预览** 页，查看新增、更新和分叉数量，确认后点击 **应用到本机**。
5. 启动 Codex 检查。回公司前，再从家里导出并推送；公司按同样方法拉取合并。

**Git 操作不会自动应用聊天结果。** 同一聊天出现分叉时，使用 **连接与设置** 中的冲突策略。默认停止后，可在预览页点击 **重新选择冲突版本**，直接使用保留的双方快照重新合并，不必再次下载。Git 中不同电脑的快照互相独立，Git 合并的只是备份提交，数据库内容由原来的专用合并逻辑处理。

### 状态和重试

底部显示当前阶段与用时，操作日志默认收起，出错时自动展开。日志记录具体的 Git clone / fetch / push 及其耗时，帮助区分网络传输与导出、压缩阶段。

工具沿用系统 Git 的 SSH、代理与凭据配置，不再强制指定 SSH 命令。首次登录或密钥解锁仍请在终端完成。网络操作默认单次最多等待 30 分钟，可在 **连接与设置** 调为 1 至 120 分钟；这只是等待上限，不代表正常上传需要这么久。

上传已经成功时，界面直接刷新本地快照清单，不再额外 fetch。**仅重试推送** 只发布本机备份提交，检测到无关文件的待推送提交会停止。若导出已完成但提交前失败，可用 **上传已有导出…** 选择该目录继续，无需再次读取正在使用的聊天库。

### 仓库内的内容

原始 SQLite 文件不会直接提交到 Git。工具先压缩成 ZIP，再分成 **48 MiB** 的数据卷；加密卷额外包含 16 字节认证标签，仍远小于 GitHub 普通 Git 的单文件限制。无需 Git LFS。

```text
codex-chat-backups/
  .codex-chat-repo.json       备份格式及加密策略
  .gitattributes
  devices/
    office/device.json       设备归属 ID
    office/latest.json       该设备最新快照指针
    home/...
  snapshots/
    office/日期时间-编号/
      snapshot.json          格式、校验值、加密参数；不含密码
      part-000001.bin
      part-000002.bin
    home/...
```

空仓库首次推送使用 `codex/chat-sync` 分支；已有仓库使用克隆得到的默认分支。每台电脑使用不同的快照目录和最新指针。客户端默认只列出每台设备的最新快照，旧快照仍留在仓库中。

### 加密与容量

默认使用 **AES-256-GCM** 加密每个分卷，并使用 PBKDF2-HMAC-SHA256、随机盐和 600,000 次迭代从密码派生密钥。每个分卷有独立随机 nonce 和认证标签；错误密码或分卷被修改会拒绝解密。设备标识、快照时间、分卷数量及大小、加密参数仍对仓库访问者可见。

第一次上传决定仓库是否要求加密。如果首次为加密上传，后续工具会拒绝未加密上传。未加密仓库也可以上传加密快照，但旧的未加密数据仍在 Git 历史中。关闭加密上传会在窗口要求你确认。

分卷解决单文件限制，**不会减少 Git 历史的累计容量**。目前每次保留一个完整压缩快照，没有自动清理、增量去重或历史瘦身；频繁备份大型聊天库会使仓库快速增大。GitHub 也有仓库总量、推送和使用政策限制，大数据量或高频备份更适合专门的备份存储。

本地导出目录、解包目录和回滚备份仍为未加密内容；加密作用于提交进 Git 的备份分卷。备份密码丢失后工具无法找回。不要把密码放进同一个 Git 仓库。

### Git 错误时的行为

- 不会 `git add -A`，仅提交工具自己生成的路径。
- 本地克隆存在未提交文件或未完成的 Git 操作时，停止，不替你清理。
- 同一设备标识已被另一份本机配置认领时，拒绝上传，避免两台电脑互相覆盖最新指针。
- 另一台电脑同时推送时，会获取更新，并在备份引用保留本机提交后重放工具自己的提交；产生冲突则撤销该次重放并停止。
- 不强制推送、不删除远端备份、不改动全局 Git 用户配置。备份提交使用工具专用的提交者名称和邮箱。
- 提交前失败时，撤销本次尚未提交的仓库文件；原始本地导出快照保留。推送失败时，已经建立的本地提交和分卷保留。点击 **仅重试推送** 即可，不需要备份密码、重新导出或重新压缩；也可以在同一仓库目录中手动 `git push`。
- 认证失败时，先在终端对同一个地址执行 `git ls-remote 仓库地址`，完成 Git 凭据管理器登录或 SSH 配置，再回工具重试。不要把访问令牌直接粘进仓库地址。

工具不会把登录凭据目录上传，聊天和数据库原本已有的私人内容仍可能进入备份。建议始终使用独立私有仓库并保留加密上传。

## 命令行

以下示例在工具目录的 PowerShell 中执行，目标路径与输入输出都需要按实际情况调整。输出目录和回滚目录不能已存在。

```powershell
# 公司电脑：关闭 Codex 后导出
python .\codex_chat_merge.py export --home "C:\Users\Autumn\.codex" --out "D:\CodexTransfer\office-01"

# 只读列出项目标识、名称、聊天数量（无需退出 Codex）
python .\codex_chat_merge.py list-projects --home "C:\Users\Autumn\.codex"

# 按项目名称或唯一标识导出；--project 可重复，也可额外选择单条聊天
python .\codex_chat_merge.py export --home "C:\Users\Autumn\.codex" --out "D:\CodexTransfer\selected-01" --project "智能家居方案" --project "project:实际项目ID" --thread "实际聊天ID"

# 家里电脑：关闭 Codex 后导出本机
python .\codex_chat_merge.py export --home "C:\Users\Autumn\.codex" --out "D:\CodexTransfer\home-01"

# 在新目录生成结果；默认冲突时停止
python .\codex_chat_merge.py merge --base "D:\CodexTransfer\home-01" --incoming "D:\CodexTransfer\office-01" --out "D:\CodexTransfer\merge-01" --target-home "C:\Users\Autumn\.codex"

# 已看过冲突报告，决定来源版用于全部分叉聊天；使用新的输出目录
python .\codex_chat_merge.py merge --base "D:\CodexTransfer\home-01" --incoming "D:\CodexTransfer\office-01" --out "D:\CodexTransfer\merge-02" --target-home "C:\Users\Autumn\.codex" --conflict incoming

# 写入本机，先建立回滚备份
python .\codex_chat_merge.py apply --result "D:\CodexTransfer\merge-02\merged" --home "C:\Users\Autumn\.codex" --backup "D:\CodexTransfer\rollback-01"

# 必要时回滚，仍需完全退出 Codex
python .\codex_chat_merge.py rollback --receipt "D:\CodexTransfer\rollback-01\receipt.json"
```

命令返回码：`0` 成功；`2` 操作未完成（包括检测到冲突、Codex 未关闭、快照校验失败）。GUI 中的大文件操作在后台线程运行，日志显示当前阶段；处理期间不允许正常关闭窗口。
